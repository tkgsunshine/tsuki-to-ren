# 鑑定エンジン（fortuneEngine.ts）の伝統方式との差の洗い出し

## 方針（ユーザー指示）
**可能な限り、伝統的な方式（四柱推命・九星気学）を踏襲する。やりたいことに対して理論的に無理な部分は、オリジナルでよい。**
- 「理論的に無理」の例: 入力が足りない（出生時刻がない）／吉凶を点数に換算する（伝統には点数がない）／MBTIとの掛け合わせ（伝統の体系の外）
- 伝統に寄せると、点数は変わる。変更のたびに、変更前後の比較（影響する人の割合・変化幅）を出してから反映する

## 現状と、伝統的な方式との差（コードで確認した事実。伝統的な方式の説明は、一般的な理解に基づく）

## 実施状況
- **P1（#2・#3・#4）: 実装（PR）。** 節入り・立春を、太陽の視黄経（Meeus の低精度式）から計算し、年・月・本命星の切替に使う。出生時刻が不明なため、判定は「その日の日本時間の正午」。精度は、天文計算（Python ephem、2000〜2030年の12節）との比較で、約25分以内
  - 本命星: 立春で切替（旧: 2/4固定）。影響は、誕生日のうち約0.2%（2/4前後）
  - 月柱: 節入りで切替（旧: 暦の月で1月=寅。約1か月ずれていた）。月運の予報の点数に影響（下記）
  - 年柱（`calculateYearPillar`）: 暦年のまま。年運の予報は、年の途中の日付で見るため結果は同じ。誕生日から年柱を使う箇所は、現状ない
- **P2（#8・#9）: 実装（PR）。** 単身の基本点と、日ごとの揺らぎを、伝統的な考え方に置き換え
  - 基本点: `80 + 日柱の十二運の点 + 本命星と日主の五行の調和（相生+8／同+4／相剋−6）`。旧: `65 + (本命星の番号%4)×8 + (十干の文字コード%5)×2`（占術の根拠なし）。定数80は、旧版の基本点の平均（82.8）に合わせた
  - 日ごとの揺らぎ（sin関数）→ 今日の十二支が、日主にとってどの運の段階か（十二運）を足す。相手がいる場合は、二人の平均。週次スコアの2日目以降にも、同じ項を足して、今日と同じ式に揃えた
  - 十二運の表は、日本で一般的な表（陽干は順行・陰干は逆行、長生は 甲=亥・乙=午・丙=戊=寅・丁=己=酉・庚=巳・辛=子・壬=申・癸=卯）。点数への換算の重み（長生+5、沐浴+1、冠帯+6、建禄+8、帝旺+8、衰−2、病−5、死−7、墓−4、絶−6、胎0、養+2）は、アプリが決めた値（原理的にオリジナルでOK）
  - P2のマージ後: 相性レーダーチャートの日替わりの揺らぎ（`dailyTick`、疑似乱数）が残っていた → P3 のPRで置き換え
- **P3（#6）: 実装（PR）。** 今日（その日）の天干が自分の日主に与える影響を、通変星（十神）の10種（陰陽で正・偏を区別）で点数化。`getTenGod` / `getDailyStemImpact` / `TEN_GOD_POINTS`。干合+16は、伝統どおり維持
  - 旧: 五行の5分類で、生剋の向きと陰陽を区別しなかった（`elementRelations` は向きのない表）。印・食傷+10／比和+4／財・官殺−16
  - 新: 正印+10・偏印+6・食神+6・傷官0・比肩+4・劫財−2・正財+2・偏財+2・正官−8・偏官（七殺）−16。点数への換算の重みは、アプリが決めた値。全体の平均が大きく動かないよう調整（天干の影響の平均 旧1.6→新2.3）
  - 週次・月運・年運の予報も、同じ関数を使うため、連動して変わる
  - レーダーチャートの日替わり値（±3以内）: 疑似乱数をやめ、今日の天干・地支・十二運と、二人との関係から決める
- **P4（#7）: 実装（PR #42 に別コミットで追加）。** 九星気学の日盤（日の九星）を計算し、本命星との関係を、今日の運勢と週次スコアに足す。`getDayStarNumber` / `getDayStarPoints` / `DAY_STAR_WEIGHT`
  - 日盤: 冬至に最も近い甲子の日から陽遁（一白から増える）、夏至に最も近い甲子の日から陰遁（九紫から減る）。冬至・夏至は、太陽の視黄経（270度・90度）から計算
  - 検証: 日本の暦サイトの日家九星と一致（2026-05-01=六白、2026-07-01=六白、2026-09-05=三碧。陽遁・陰遁の両方）。2025-12-21 は冬至の甲子日で一白。中国系サイト（skillon）の日の飛星は、別の方式で、一致しなかった（採用しない）
  - 点数: 日の星が本命星を生む+4／同じ五行+2／本命星が日の星を生む−1／本命星が日の星を剋す0／日の星が本命星を剋す−4。重みは、アプリが決めた値
  - 対象外: 方位の吉凶（五黄殺・暗剣殺など）、月盤・年盤の中宮との関係。別の段階
- **レーダー不具合の修正（ユーザー決定 d4）: 実装（PR）。** ペア鑑定のレーダーの相性判定が、平易な名前（運命の絆・最高のフィーリング・運気アップなど）に改名された後も、旧名（干合・支合・相生など）と比べていたため、一度も働かず、既定値だけだった。平易な名前から元の関係に戻して比べるようにした（レーダーのみ。相性タイトルの文言は、専門用語が出てしまうため、そのまま）
- **16タイプの「理想の組」の不具合の修正（ユーザー決定 d10）: 実装（PR）。** アプリの「理想の組」の表が、一方向にしか書かれていなかったため、ENFP×INFJ・ENFP×INTJ・ESFP×ISTJ は、「あなた」と「相手」を入れ替えると、16タイプの点数（最大40点）が変わっていた。組（無順序）で持つようにして、どちらの順でも40点にした
- 先に実施済み: 日柱の基準日の修正、今日の運勢への十二支の関係の追加（週次と同じ強度）
- **今日の点数の＋への偏り・100点の出すぎの修正（ユーザー決定 2026-11-03）: 実装（PR）。** 変更前は、今日の点数が基本の点より高い日が約7割（二人の鑑定で差の平均+9.5点）、一人の鑑定では1日あたり2〜3割の人が100点に張り付いていた
  - 二人の鑑定: 今日の天干・十二支の影響を、二人の合計から二人の平均に（十二運・日の九星はもともと平均）。週次スコアも同じ
  - 同じ十二支どうしを三合（+12）から外し、比和（五行が同じ、+2）として扱う（伝統では、三合は異なる支どうしの結びつき）。`getBranchImpact` を使う月運・年運・守護獣の相性（X投稿用）も連動して変わる
  - 今日の4項目（天干・十二支・十二運・日の九星）は平均がプラス（合計 約+4.8点）なので、`DAILY_CENTER_OFFSET = -5` を足して、＋と−がおおよそ半々になるようにした（アプリが決めた値）
  - 一人の基本点の定数 `SOLO_BASE_CONSTANT` を 80 → 70（アプリが決めた値）。100点の上限に届きにくくするため
  - 対象外: 同じ十二支のうち自刑（辰辰・午午・酉酉・亥亥）を凶として扱うこと。月運・年運も二人の合計のまま（今回は今日・週次のみ）
- **「2人の最高シンクロ日」「恋の星」と今日の点数のずれの修正（2026-11、TAKASHI確認待ち）: 実装（PR）。** シンクロ日・恋の星の日の今日の点数が、ふつうの日より低く出ることがあった（シンクロ日の約2割が、その二人の90日の中央値未満）
  - 伝統との差: 正官・正財は伝統では吉の星（四吉神）で、女性の正官・男性の正財は異性・恋人の星。`TEN_GOD_POINTS` は男女を区別せず正官をマイナスにしていたため、恋の星の日に点数が下がっていた。今日の点数では、恋の星の日だけ専用の点数に置き換える（干合の日は干合のまま）。`TEN_GOD_POINTS` 自体は基本の相性にも使うので変えない
  - 天乙貴人（伝統では強い吉の星）と空亡（伝統では運の空白＝凶）を、今日の点数に足す（それまで今日の点数に入っていなかった）
  - 2人の最高シンクロ日（印の重ね方の判定はアプリのオリジナル）にボーナスを足す。判定は「2人の最高シンクロ日」欄と同じ関数（`isPairSyncDay`）
  - 印の判定（`getPersonDay` など）は `luckyDays.ts` から `fortuneEngine.ts` へ移した（メール用の自動生成コピーでも同じ計算にするため）。週次グラフも同じ式。`DAILY_CENTER_OFFSET` を合わせ直した
  - 点数への換算の重みは、アプリが決めた値。対象外: 相性レーダーの日替わり値、月運・年運
- **16タイプ不明時の基本の相性の満点（2026-11、TAKASHI決定：平均を保つ形）: 実装（PR）。** どちらかの16タイプが分からないと、16タイプ相性を一律20点（40点中）にしていたため、生年月日の相性が最高でも基本の相性は80点で止まっていた。不明のときは、四柱推命（日干30点）＋九星気学（本命星30点）の60点満点だけで、`100 − (60 − 合計) × 2.5`（`MBTI_UNKNOWN_STRETCH`）にする。下限は従来どおり30点。倍率はアプリが決めた値で、平均を旧版とほぼ同じ（約66点）に保つ。伝統の判定そのものは変えない
  - 影響: 16タイプ不明の二人の鑑定のみ。−21〜+20点（平均+0.3点）。生年月日の相性が高い組は上がり（最高100）、低い組は下がる（最低30）
  - 単純な換算（60点→100点）は、平均が77.6点になり、16タイプありの平均（66.0点）より高くなるため採用しなかった

## 進め方の案（優先順）
1. **P1: 節入り・立春の計算（#2・#3・#4）。** 客観的で、検証もしやすい。月柱の約1か月のズレを直せる
2. **P2: 単身の基本点と揺らぎ（#8・#9）。** 伝統に根拠のない部分を、五行バランスなどに置き換える
3. **P3: 今日の運勢の通変星・十二運化（#6）。**
4. **P4: 九星気学の日盤（#7）。** 検証用の正解データが必要
5. **P5: 出生時刻の任意入力（#5）。** プロダクトの判断（入力項目を増やすか）

各段階で、変更前後の比較（影響する人の割合、変化幅）を、PRに載せる。

## 二人の相性100（2026-11-12 追加。既存の点数は変えない）
- **ランキング50（16タイプだけ）**: 伝統的な方式（四柱推命・九星気学）は使わない。16タイプの4文字の組み合わせと、アプリの16タイプ相性表（mbti-compat.json）から、お題ごとに136組の順位を出す。**全体がオリジナル**（理論上、伝統的な方式に対応するものがない）。式は X投稿のカップル相性ランキング（scripts/x/lib/couple-rank.mjs）と同じで、`src/utils/coupleRank.ts` に移し、`scripts/test-couple-rank.mjs` で X側と順位が一致することを確認している。
- 基本の相性・今日の相性・年次などの点数の関数は呼ぶだけで、変更していない。
- **本格鑑定50（16タイプ×四柱推命×九星気学）**: `src/utils/coupleReading.ts`。
  - 伝統どおりの判定: 日干どうしの干合・相生・比和・相剋、日支どうしの支合・三合・冲・五行の関係、本命星どうしの相生・比和・相剋。時期のお題は、年柱・月柱の十二支と二人の日支の支合・三合・冲、その年の九星（年盤の中宮）と本命星の五行の関係。
  - 伝統との差・オリジナル: お題ごとにどの判定をどれだけ効かせるかの重み、★1〜5と「上位◯%」への換算（日柱60×60・本命星9×9・16タイプ16×16を同じ重みで数えた分布）、16タイプとの掛け合わせ。年運は通変星（十神）や年盤での本命星の位置（回座）までは見ず、五行と十二支の関係だけを使う（簡略化）。月の動きも日支と月支の関係だけ。
  - 根拠の文には、そのお題で使った判定だけを書く（`scripts/test-couple-reading.mjs` で確認）。
